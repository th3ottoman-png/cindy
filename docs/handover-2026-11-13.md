## 6. Traps learned this session (save hours)

- `lldb` cannot expand argv for this repo's spaced, `=`-heavy path (`lldb-argdumper exited with error
  1`): run from `apps/desktop` and pass a relative `../../node_modules/vitest/vitest.mjs`.
- After a crash, lldb's queued `-o` commands never run because the process finishes exiting the moment
  it stops. Attach commands with **`-K <file>`** (source-on-crash).
- `NODE_OPTIONS=--report-on-signal --report-signal=SIGSEGV` **swallows** the fault (33 reports, process
  alive 18 min). Do not use it to capture a crash.
- `MallocScribble=1 MallocGuardEdges=1` raises the SIGSEGV rate but fails 17 tests and writes libmalloc
  noise to stderr that breaks two runner tests.
- macOS bash is 3.2: no `mapfile`.
- `kill %1`-style job control and `mapfile` are unreliable in the tool shell; prefer explicit PIDs and
  `while read` loops.
- The `=` in the repo path is read as an assignment by `env -i` and by lldb's shell expansion.
- A `python3` heredoc that asserts silently skips later edits if an assertion fails — apply edits one
  at a time with per-edit asserts.
