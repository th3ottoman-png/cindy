## 6. Traps / harness quirks learned (save hours)

- **ECC specialist subagents 404 here.** Agent-tool delegations to `typescript-reviewer`,
  `code-reviewer`, etc. fail instantly with "404 Model not exist" in this harness. Do reviews INLINE
  (or a fork, which inherits the host model). Don't burn attempts on specialist delegation.
- **exec `run_shell_command` output carries a wrapper** (`Command:`/`Directory:`/`Output:`/`Error:`/
  `Exit Code:`/`Signal:`/`Process Group PGID:`). Never use `.output` as file content. After any
  exec write/append to a markdown doc, re-read the region and grep for `PGID`/`Exit Code:`/`Signal:`
  to strip leaked wrapper before committing.
- **Backtick-heavy content via exec template literals breaks** ("unexpected end of string"). Use a
  quoted heredoc `cat <<'EOF' > path`, or escape backticks, or use `write_file`. For ROADMAP/STATUS
  splices, write a Node script via heredoc that reads a content file and splices by line index.
- **`sleep N; <follow-up>` in one command is blocked.** Run a standalone `sleep N  # intentional-sleep:
  <reason>`, then inspect background `shell-<id>.output`/`.status` files in a SEPARATE call. Prefer
  `is_background:true` for anything long-running.
- **`read_file` can return an "unchanged since last read" stub** instead of fresh content — use shell
  `cat`/`node -e` when you need the current bytes.
- macOS bash is 3.2 (no `mapfile`); the `=` in the repo path is read as an assignment by `env -i` and
  lldb shell expansion; quote every path.
- A PostToolUse Prettier hook rewrites TS files with double quotes — if you write TS through a shell
  heredoc, expect that; prefer the edit/write tools and match house style.
