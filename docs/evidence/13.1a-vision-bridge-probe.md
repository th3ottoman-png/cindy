- **Label:** `live-proven` (a real Hermes 0.23.0 turn ran `vision_analyze` against a configured

## Method

1. **Probe home (a copy, never the shared base config, never `~/.hermes`).**
   `/tmp/proofs/13.1a/probe-home` symlinked `installs` (the 597 MB venv), `.env`, `auth.json`,
   `SOUL.md` from `~/.hermes-cindy` (the same shared items `prepareSessionHome` links). A fresh
   empty home fails with `no dependency environment is committed for this install` — the `installs`
   symlink is what makes a home runnable. The generated `config.yaml`:
   ```yaml
   model: { default: deepseek-flash, provider: deepseek, base_url: 'https://api.deepseek.com/v1' }
   custom_providers:
     - { name: lmstudio-local, base_url: 'http://127.0.0.1:1234/v1', context_length: 65536 }
   auxiliary:
     vision: { provider: lmstudio-local, model: google/gemma-4-26b-a4b-qat, base_url: 'http://127.0.0.1:1234/v1' }
   ```
   The real `~/.hermes-cindy/config.yaml` was read for reference only, never modified.
2. **`--image` is rejected by the gateway CLI.** `hermes chat --image … --format stream-json` →
   `Error: Unsupported gateway CLI options: --image. … use hermes --tui or the Desktop app to attach
   the image` (RC=2). This confirms why the Cindy adapter sends path-reference text
   (`agent.ts:186-190`) rather than an inline image.
3. **The turn (Cindy flow).** Query (via `--query-file`): `Attached image \`01-squads-tab.png\`
   (image/png) located at: \`/tmp/proofs/12.4b/01-squads-tab.png\` … Describe this image and quote any
   text you can read in it.` Run: `HERMES_HOME=<probe> HERMES_MGR_CHILD=1 hermes chat --query-file …
   --oneshot --format stream-json --yolo -m deepseek-flash --provider deepseek
   --base-url https://api.deepseek.com/v1 --max-turns 12`. The image is the 12.4b Squads-tab
   screenshot (known text: "Proof squad", "Squads", "Launch").

## What this proves

- **`vision_analyze` reads `auxiliary.vision`.** The vision request resolved the named custom
  provider `lmstudio-local` (the configured `auxiliary.vision`), while `title_generation`
  auto-detected the main `deepseek` provider. Vision did not fall back to the chat provider.
- **The image is bridged to the chat model.** DeepSeek (chat) called `vision_analyze`; the local
  Gemma route analysed the base64 image and returned text the chat model used.
- **Key handling.** A local provider with no `key_env` sends a `no-key-required` placeholder; an
  API vision route would use its `key_env` (env only). Nothing is written to the file.
- **Gateway CLI cannot attach images inline** (`--image` unsupported) — the path-reference text
  flow is the right (and only) gateway path, matching the Cindy adapter.

## Decision

**Design A (native Hermes auxiliary)** — see ADR 0013. 13.1 writes `auxiliary.vision` into the
session home from the resolved `vision` route at home preparation; no Cindy pre-describe path.
