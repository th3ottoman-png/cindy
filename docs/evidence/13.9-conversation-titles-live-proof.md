## Two defects found by the live run

1. **The baseline hook was on the wrong path.** `noteAutoTitleWritten` was first called only at the
   end of `runUnsynchronized`, but auto-title returns early when the model yields nothing — so no
   baseline was ever recorded and every check failed closed with `owner-renamed`. Moved to the
   point where the user-text placeholder actually lands. Found live, fixed, re-proven.
2. **The existing title path cannot authenticate against tokenhub.** The first proof attempt logged
   `routed title generation unavailable — failing closed … HTTP 401` from
   `auxiliary-title-one-shot`. That module calls `requestRoutedTaskText(args)` with no env override,
   so a key stored in `~/.hermes-cindy/.env` is invisible — the same mechanism as the existing
   `maker:routing:request-task-text` Debt row, now confirmed to affect auto-title and the Magic
   button too. `RetitleHost` passes `env: harnessDiscoveryEnv` and authenticated first try. Recorded
   in Debt; not fixed here (out of this row's scope).

## Ownership is re-checked after the model call

The conditional write (`WHERE title = expected`) cannot catch an owner who renames to the *identical*
string during the call — the same edge the existing auto-title path guards explicitly. `RetitleHost`
therefore re-reads ownership after the routed call and before writing, and returns `owner-renamed`
without touching the title. Covered by a host test that renames mid-call from inside `fetchImpl`.

## Design decision: fail closed for sessions with no record

A session this feature never wrote a title for has no durable ownership record, so it is treated as
owner-renamed and never re-titled. This is deliberate: an owner rename that predates the feature
must not be overwritten, and the `sessions` table has no "who wrote it" column. New conversations
get a baseline from their first auto title. The 84 pre-existing conversations keep their titles.
