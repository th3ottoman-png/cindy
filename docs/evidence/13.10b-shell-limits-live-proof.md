## What was built

- NEW `packages/maker-hermes-manager/src/shell-limits.ts`: narrow reader for
  `~/.cindy-harness/shell-limits.yaml` (`timeout_seconds`, default **300**, 0 = leave the Hermes
  default alone, upper bound **600** because that is Hermes 0.23's foreground hard cap; a missing
  file gives the defaults; unknown keys and bad values are listed and fall back), a 2 s cached
  loader, and `injectTerminalTimeout` — a keep-formatting writer that adds or replaces
  `terminal.timeout` and leaves every other byte (comments inside the block, nested keys, other
  top-level blocks, CRLF) untouched. It refuses an inline `terminal: {…}` value instead of
  corrupting it.
- `hermes-manager.ts`: the limit is read per session-home prepare and written through the same
  `transformConfig` chain as the vision route and the hook block, so it lands in **each session
  home's** `config.yaml` and never in the base home. `0` writes nothing, so a home that had a
  limit loses it on the next prepare.
- Desktop: IPC `maker:shell-limits:get` (`main/maker-ipc/shellLimits.ts`, a local file read; a
  malformed load reads as unavailable), preload + `vite-env.d.ts`, and `ShellLimitsChip` in the
  8.2 session manifest strip (`shell 300s` / `shell default`, error state when the file's values
  were rejected, re-read every 10 s).
- `packages/maker-shared/src/shellLimitNotice.ts` (`@cindy/maker-shared/shell-limit-notice`):
  `parseShellTimeoutNotice` reads the two markers Hermes 0.23 prints
  (`[Command timed out after Ns]`, `Command timed out after N seconds`), and `AgentActionRow`
  renders one badge in the tool row: **`stopped at 5 s`**.
- `max_output_chars` is **not** implemented: 13.10a proved Hermes 0.23 has no output-cap setting.
  The file reports it as ignored with the reason, and the cap is recorded as a follow-up row
  (13.10c).

## Limits, written down

- A per-call `timeout=` in the model's own tool call still **overrides** the config (13.10a), so
  this is a default, not a ceiling. The row does not claim otherwise.
- The badge only appears on a row whose result carries a timeout marker; a command that was
  killed by something else (SIGKILL from the guard, for example) is not marked.
- `max_output_chars` is not built: no Hermes setting exists (13.10a), and the blueprint says not
  to rewrite tool results in the stream. Follow-up row 13.10c.
