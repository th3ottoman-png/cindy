# 1.8c live proof: per-session model switch against the real Hermes CLI (2026-10-30)

Hermes Agent v0.22.5, real `~/.local/bin/hermes-cindy` and `~/.hermes-cindy`, default model `deepseek-flash`. Paid DeepSeek turns (each prompt: "Reply with exactly the
single word OK", no tools; ~15k input tokens, 1 API call), owner-authorised. Harness: a throwaway vitest file (deleted) that starts the production `HermesManager`
(socket, registry, `startHermesRun`) in-process and drives it over the RPC socket in a Full-access session. **The desktop UI path (ChatInput → IPC → agent) was NOT
exercised**: see ROADMAP 1.8c-2. `~/.hermes-cindy/config.yaml` backed up to `config.yaml.bak-20261030-1.8c`; byte-identical after every run.

## Before (commit `322d14a672`): the 1.8a design is broken on the real CLI
`query/setModel` then a second turn: the daemon resumed with a changed `-m`.
```
turn 1: model=deepseek-flash   result "OK"                         (API call #1 model=deepseek-flash)
turn 2: exit_code 2, 0 tokens: "Resume retains gateway session policy; creation overrides are unsupported on resume.
        -m/--model differs from this session's launch: resume without it and use /model after resuming to switch."
```
The 1.8a unit tests passed because the fake Hermes accepts any flags.

## Free probes (resume of that session, `/model` is a local command)
```
--safe-mode                                  -> rejected ("--safe-mode differs from this session's launch")
--safe-mode -m deepseek-flash --provider ... -> rejected (-m, --provider, --safe-mode all "differ")
--yolo --provider deepseek                   -> rejected ("--provider differs")
(no flags)  "/model deepseek-v4-pro"         -> "Model switched to `deepseek-v4-pro` ... (session only) ... Applies from your next message."
next plain resumed turn                      -> API call #1: model=deepseek-v4-pro   (a later resume in a new process kept it)
```
Rule: a resume must repeat the launch flags exactly; the model changes only through `/model`.

## After (this change, ROADMAP 1.8d): same harness, fresh session
```
turn 1 (no override)          session ...987a51..  API call #1: model=deepseek-flash   result "OK"  closed: completed
setModel deepseek-v4-pro
turn 2 (daemon: /model run, then the turn, both resume with the launch flags)
                              session ...987a51..  API call #1: model=deepseek-v4-pro  result "OK"  closed: completed
```
The `/model` pre-run emits no events to the client (only 2 result events for 2 turns). Home `config.yaml` untouched.

## Not covered
- The desktop UI (pick a model in ChatInput, header label updates) and Full-access only here. Safe-mode (`--safe-mode`) resume + switch is `unit-tested` with the fake, not run live.
- Clearing the override (`''` → switch back to the home default) is unit-tested only.
- A `/model` the user types into the chat themselves is not tracked in `appliedModel`; the next Cindy override may skip or repeat a switch.
