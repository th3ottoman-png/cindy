## Resolver refinement found by the proof

The first live attempt used `getReadyBinaryPath(kind) ?? getCachedBinaryStatus(kind).binaryPath`.
`getReadyBinaryPath` returns the prepare() cache, which holds a **stale path** after the binary is
removed, so the card showed `error` (spawn ENOENT) rather than `missing`. For a read-only status
card the fs-verified `getCachedBinaryStatus` is the right resolver: it re-checks executability and
falls through to the dev binary, so a removed binary resolves to no path → `missing`. Changed
`resolvePath` to use `getCachedBinaryStatus` only; the missing demonstration then rendered correctly.
