## What shipped

- New `recap` task class in `TASK_CLASSES` (`routingFile.ts`) and `RoutedTaskClass`
  (`routed-auxiliary.ts`). Not routed = off, no fallback to the chat model.
- New pure module `packages/maker-core/src/recap/recap.ts`: `shouldRecap` (fixed rule order,
  one recap per away period), `buildRecapPrompt` (24 000-char budget ≈ 6 k tokens, drops the
  OLDEST turns, truncates a single oversized newest turn rather than dropping it),
  `readRecapConfig` / `writeRecapConfig` (atomic), `RECAP_SYSTEM_PROMPT` (new text for a new
  feature only; no existing prompt edited).
- New `RecapHost` (`apps/desktop/src/main/maker-ipc/recap.ts`), modelled on `ChatSummaryHost`.
  15 s timeout, 1024 max tokens, one in-flight call per session, per-session `lastRecapTurn`.
- IPC `maker:recap:get-config` / `set-config` / `on-focus` / `dismiss`; preload + `vite-env.d.ts`.
- `RecapStrip.tsx` mounted above `ChatInput` in `CCAgentSessionView`. The away clock lives in a
  module-scope map so it survives the component unmounting on a session switch; it starts on
  unmount and on window blur, and is read on mount and on window focus.
- `RecapSection.tsx` in Settings → Personalization: on/off, away minutes, and a hint that names
  the route and model when routed, or says "Off until routed … API routes bill per call" when not.

## Two real defects found by the live run

1. **`maxTokens: 200` produced an empty reply.** The first attempt reached the API and failed
   with `reply has no message content`: `deepseek-v4.1-flash` is a reasoning model and spent the
   whole 200-token budget thinking. Raised to **1024**, after which the strip rendered. Recorded
   in the code comment so the number is not "tidied" back down.
2. **The route the council block names no longer exists.** The first attempt used
   `deepseek-v4-flash-202605` (copied from the managed `cindy-council` block) and failed closed
   with `model-missing`: *"tokenhub is online but does not list model
   deepseek-v4-flash-202605"*. The live `/models` catalog has `deepseek-v4.1-flash`,
   `deepseek/deepseek-flash`, `glm-5.3-flash`, … but not that name. **The fail-closed behaviour
   worked exactly as designed — no silent fallback.** The stale name in the council block is
   reported to the owner, not edited here (it is a managed block and out of this row's scope).

Also observed, and recorded as a new Debt row rather than fixed here:
`maker:routing:request-task-text` (`providersHandlers.ts`) passes only `harnessDir` and
`routedTaskDeps`, and `register.ts` never supplies `routedTaskDeps`, so that IPC resolves keys
against `process.env` alone. A key the owner stored in `~/.hermes-cindy/.env` (TOKENHUB_API_KEY)
is invisible to it and the call returns **HTTP 401**, while `maker:providers:discover` on the same
provider succeeds because it does get `discoveryEnv`. `RecapHost` avoids the trap by passing
`env: harnessDiscoveryEnv`.

## Cost and state left behind

- **Spend:** two tokenhub `deepseek-v4.1-flash` generation calls (one empty-reply failure at 200
  tokens, one delivered strip at 1024) plus the pre-flight `/models` probes. Owner-authorised.
- `~/.cindy-harness/routing.yaml` keeps the new `cheap-api` route and `recap: cheap-api` rule, so
  the feature is live for the owner. Backed up first to
  `routing.yaml.bak-2026-11-14-13.3` (byte-identical restore available).
- `~/.cindy-harness/recap.json` = `{"enabled": true, "awayMinutes": 15}` — the defaults.
- Ongoing cost: at most one small flash call per session per away period, only after ≥ 4 user
  turns and ≥ 15 minutes away, never while a turn runs. The strip names the route every time.
  Turn it off with the Settings checkbox or by removing the `recap` rule.
