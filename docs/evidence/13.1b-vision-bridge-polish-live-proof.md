# 13.1b — Vision bridge polish (notice + manifest strip + bypass) live proof

- **Date:** 2026-11-14. **Hermes:** 0.23.0. **Label:** live-proven. Completes ADR 0013 Design A (13.1 core).
- **Scope:** the three polish items split from 13.1 — the not-routed one-line notice, the manifest strip
  `vision -> <route>`, and the chat-model-has-vision bypass.

## What changed (feature code)
- `maker-hermes-manager/hermes-manager.ts`: in the query/send path, when the turn text carries an attached
  image, the chat model's provider does not declare vision, and `vision` is not routed, emit a
  `hermes-mgr/vision-notice` event. The send is never blocked. Bypass: `homeForSession` skips
  `injectVisionRoute` when `providerDeclaresVision(session.provider)` is true.
- `maker-core/providers/vision-route.ts`: `providerDeclaresVision(providerId)` — fail-safe; a provider absent
  from providers.yaml (e.g. the Hermes built-in deepseek) returns false so the bridge stays on.
- `maker-core/agents/hermes/translator.ts`: normalize `hermes-mgr/vision-notice` -> `{kind:'vision-notice',message}`.
- `maker-core/agents/hermes/agent.ts`: `vision-notice` case emits a durable `standaloneText` one-liner
  (same pattern as `resume-reset`).
- `maker-core/session/session-manifest.ts`: a `model-route:vision` capability when `routing.rules.vision`
  names a valid route (the renderer already feeds routing facts).

## Method + result
1. **Notice (real daemon).** Drove the real `HermesManager` (tsx + RpcClient over its socket) with a probe
   home; temporarily removed `rules.vision` (backed up `routing.yaml.bak-20261114-13.1b`), then query/start +
   query/send with the path-reference image text and chat=deepseek-flash. Captured notifications:
   `hermes-mgr/vision-notice` = `{"message":"This model can't see images. Route vision in routing.yaml."}`,
   followed by `system/init`, `session-bound`, `result` — the turn still ran (send not blocked). Restored routing.
2. **Manifest strip (live data).** `buildSessionManifest` fed the live routing.yaml produced
   `model-route:vision` = label `vision gemma-local`, value `lmstudio-local/google/gemma-4-26b-a4b-qat`,
   locator `rules.vision -> gemma-local`, file `~/.cindy-harness/routing.yaml`.
3. **Bypass (live data).** `providerDeclaresVision('deepseek')` = false (chat model not in providers.yaml ->
   bridge stays on); `providerDeclaresVision('lmstudio-local')` = true (vision-capable -> bridge skipped).

## Unit coverage (new)
- translator.test.ts: vision-notice normalization (+ empty message -> unknown).
- agent.test.ts: vision-notice -> durable standaloneText one-liner; the model reply still arrives.
- session-manifest.test.ts: vision row present when routed; absent when not routed / unknown route.
- vision-route.test.ts: providerDeclaresVision true/false/unknown/undefined (fail-safe).

## Notes / limits
- The notice fires when the image is in the turn text (the adapter's path-reference flow); the daemon's
  structured `images` field is still rejected (reserved), so text detection is the correct signal today.
- The bypass is an optimisation: writing auxiliary.vision when the chat model can already see is harmless.
  Unknown chat-model provider -> bridge stays on (fail safe).
- Real `~/.hermes-cindy/config.yaml` untouched; routing.yaml restored after the unrouted proof.
