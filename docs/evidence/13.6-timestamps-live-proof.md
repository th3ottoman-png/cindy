# 13.6 — Always-visible message timestamps (live proof)

- **Date:** 2026-11-14
- **Row:** ROADMAP 13.6. Blueprint §8.
- **Environment:** Node v22.23.4, dev app `CindyGlobal-dev2-dev` from the canonical wrapper
  (`DESKTOP_DEV_VERDICT=ready`, pid 25015, CDP 9222), commit `9ea547ae96` + this row's diff.
- **Cost:** no model turn, no API call, no new outbound request. Local CDP + localStorage only.

## What shipped

- `showTimestamps: boolean` (default `false`) in `ResponsePreferences`, same `v1` storage key.
  `parseResponsePreferences` only accepts an explicit `true`, so a stored value without the field
  stays off.
- `formatMessageClock(createdAtMs, nowMs)` in `useRelativeTime.ts`: `HH:MM` for a message from
  today, `MMM D, HH:MM` otherwise. Pure; derived from the message's own persisted timestamp.
  `nowMs` only decides "is it today".
- `MessageActionBar`: the fade now gates an inner **action group**; the clock is a sibling of that
  group in the same slot the hover-only time occupies, so it survives an unhovered row. With the
  preference off the DOM keeps the previous behaviour (relative text inside the gated group).
- Settings → Personalization → Response style: an "Always show the time" checkbox (English only,
  no new translation keys, per AGENTS.md).

## Live proof (session `5be0ad2a`, messages from 2026-11-12 and 2026-11-14)

Driven through the real Settings checkbox and real navigation, reading the rendered `<time>`
elements. `gated` = some ancestor carries `opacity-0` (i.e. hover-only).

```
{"text":"2 days ago","dt":"2026-11-12T08:01:34.509Z","gated":true}
```

**Preference on (clicked in Settings):**

```
{"text":"Nov 12, 07:57","dt":"2026-11-12T07:57:01.564Z","gated":false}
{"text":"Nov 12, 08:01","dt":"2026-11-12T08:01:34.509Z","gated":false}
```

Older day → `Nov 12, 07:57`; today → `12:07`. Both visible without hover. The absolute tooltip is
unchanged, and the relative text is **replaced**, not duplicated.

**After a full page reload:** identical to "on" — `showTimestamps:true` survived in
`cindy.responsePreferences.v1` and the same six clocks rendered ungated.

**Toggled off again:** identical to the "off" snapshot — relative text, `gated:true`. The default
experience is restored exactly.

## Honest limitation

The clock renders wherever `MessageActionBar` mounts: user messages and the turn's final assistant
body (`showActionBar`). Intermediate assistant chunks do not mount an action bar at all, so they
get no timestamp — that is pre-existing behaviour, not changed by this row. In the proof session
that is 6 of the visible messages. The sidebar's own session-list times are a different component
and are untouched.

## State left behind

The preference was toggled back **off**, so the app is in its default state. No session data,
transcript or file was modified. Dev app stopped after the proof.
