## Two defects found by the live run

1. **A finished group is a deferred history group.** The first live turn (`Worked for 45s`) was
   never labelled: by the time the turn ends, the top-level work group is projected from the history
   view with **empty `children`** (fiber inspection: `children: []`, `deferred` set), so the renderer
   had no tool calls to send and no first tool-use id to key on. Fixed: the cache key is the group's
   own render key `work-<anchor client id>` (the anchor is the persisted client id, so it is stable
   across reloads and restarts — proven above), and a deferred group's calls are read from its
   persisted range through the existing `localDb.messages.historyView` + `workDetails` reads
   (`content: { toolName, input }`). Unit-tested; re-proven live.
2. **Small local models miss the contract sometimes.** A direct probe of `qwen3-8b` with the same
   prompt returned `""`, `"Listed proofs dir, Counted cdp.mjs lines"`, `""` in three tries, and one
   live reply was rejected as too long. An empty reply arrives as `kind: failed` ("no message
   content"). Fixed: one retry per group on a failed or rejected attempt (at most 2 calls, unit-
   tested). Both live labels then landed on the first attempt.

## Design decisions

- **Top-level groups only.** A finished turn with interim prose folds into one outer group with inner
  action groups; only the top-level header is labelled (the one visible when scrolling back
  collapsed). Inner groups keep the generic header. One call per finished top-level group, not one
  per inner group, keeps background spend small.
- **No "Label past groups" backfill button.** The blueprint makes it optional; history groups keep
  the generic header. Not built.
- **Header swap, not wait.** The header renders the generic text first and swaps when the label
  arrives through the store.
