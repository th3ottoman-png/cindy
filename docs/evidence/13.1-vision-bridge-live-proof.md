# 13.1 — Vision bridge (ADR 0013 Design A) live proof

- **Date:** 2026-11-14. **Hermes:** 0.23.0 (pin 0.22.7). **Label:** live-proven (core bridge).
- **Scope proven here:** Cindy resolves the `vision` route and writes `auxiliary.vision` into the
  session home; Hermes' `vision_analyze` then uses that route for an attached image while the chat
  model is text-only. The not-routed notice, manifest strip entry, and chat-model-has-vision bypass
  are tracked as the remaining 13.1 polish (see ROADMAP).

## What changed (feature code)
- `packages/model-providers/src/routingFile.ts`: `TASK_CLASSES += 'vision'`.
- `packages/maker-core/src/providers/routed-auxiliary.ts`: `RoutedTaskClass += 'vision'`.
- `packages/maker-core/src/providers/vision-route.ts` (new): `resolveVisionRoute()` — fail-closed;
  a route whose provider lacks `capabilities.vision: true` is `blocked` naming the route.
- `packages/maker-hermes-manager/src/vision-route.ts` (new): `injectVisionRoute()` keep-formatting
  writer (same discipline as `injectAutoReviewHook`); registers the provider in `custom_providers`
  when absent; key travels as `key_env` NAME only.
- `hermes-manager.ts homeForSession`: transformConfig now also applies `injectVisionRoute` when the
  vision route resolves (skipped for chat-only sessions).

## Method
1. Backed up `~/.cindy-harness/routing.yaml` + `providers.yaml` to `.bak-20261114-13.1`.
2. Set `lmstudio-local` `capabilities.vision: true`; added `rules.vision: gemma-local`
   (route -> `google/gemma-4-26b-a4b-qat`).
3. Ran the REAL `resolveVisionRoute()` + `injectVisionRoute()` (tsx) against the live harness and the
   base `~/.hermes-cindy/config.yaml` to build `/tmp/proofs/13.1/home` (symlinked installs/.env/
   auth.json/SOUL.md/skills/plugins/memories). Generated block:
   ```yaml
   auxiliary:
     vision:
       provider: "lmstudio-local"
       model: "google/gemma-4-26b-a4b-qat"
       base_url: "http://127.0.0.1:1234/v1"
   ```
4. Turn (Cindy path-reference flow): `HERMES_HOME=/tmp/proofs/13.1/home HERMES_MGR_CHILD=1 hermes chat
   --query-file … --oneshot --format stream-json --yolo -m deepseek-flash --provider deepseek` with the
   12.4b squads-tab screenshot (`/tmp/proofs/12.4b/01-squads-tab.png`).

## Result
- `resolveVisionRoute()` -> `{kind:'routed', route:{provider:'lmstudio-local', model:'google/gemma-4-26b-a4b-qat', baseUrl:'http://127.0.0.1:1234'}}`.
- DeepSeek (text-only chat) called `vision_analyze` repeatedly; every `tool_result` was
  `{success:true, analysis:…}` accurately describing the dark-themed agents/squads UI and quoting
  sidebar labels (New / Capabilities / Library / Agents) and the squad card.
- `logs/agent.log`: `resolve_provider_client: named custom provider 'lmstudio-local'` — vision used the
  auxiliary route, NOT the chat provider; `Image analysis completed`; keyless local endpoint sent the
  `no-key-required` placeholder (correct). No fallback to deepseek for vision.
- The 300s harness timeout killed the turn while the chat model was still synthesising its final answer
  (after 5+ successful vision calls); the bridge itself is fully evidenced by the tool results + log.
