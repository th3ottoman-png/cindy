## 3. The orphan-home finding that changed the design

The three real orphan homes were **18.7 h, 20.2 h and 20.2 h idle** — under the reaper's 24 h
window, so a literal reading of ADR 0014 Tier 1 left 2.95 GB unreachable for hours and
`retentionDays` could never touch them.

`reapOrphanHomes`' own comment says the window "Guards a record that is not flushed yet". It is a
latency guard, not a reachability rule. 13.2c therefore adds one fact: an orphan home is removable
when idle ≥ 24 h **or** `sessions.json` was itself written after the home's last activity. The
registry is one daemon writing its whole map atomically (ROADMAP 0.5), so a write since the home's
last activity proves the missing record is authoritative. Recorded as an ADR 0014 addendum, with
5 planner tests and 2 host tests. Every other guard is unchanged and an unknown fact keeps the
24 h behaviour.

## 6. Both sessions reopen and continue

Whole-home removal is orphan-only, so the "pruned session" case is a registered session whose
home **bulk** was pruned (catalog + etag + logs + cache catalogs).

| Session | Home | Reopen | Turn | Reply |
|---|---|---|---|---|
| `ef62593b` (pruned bulk) | `0383742b-…-2c0d8b21bd` | full history, 6355 chars, marker `PONG_24B_CONFIRMED` present | local `qwen3-8b` | **`PRUNE_CONTINUE_OK`** exact, 16.1k tok |
| `5be0ad2a` (recent control) | untouched | 6147 chars | local Gemma | **`RECENT_CONTINUE_OK`** exact, 16.0k tok, Done 28 s |

The pruned home's `state.db` (1 392 640 B, mtime Nov 4) was never written by the prune, and the
catalog was **not** re-fetched: the local route does not need models.dev, which is direct evidence
that the catalog is optional bulk rather than state.

Both turns showed `Hermes no longer has the previous session, so this message starts a new one.`
That is the **pre-existing cross-restart defect**, proved on an untouched home in 13.2a and
promoted to ROADMAP **1.14** by the owner this session. It is not caused by the prune: the control
session's home was never touched and reset identically.

## 7. Startup prune

`pruneAtStartup` stays **off** (the default). Unit-tested: when on, it protects every registered
session because no window is open yet, and still removes orphan homes, caches and old backups;
when off it returns null and touches nothing. Not exercised live — enabling it would delete
without a preview on the owner's next boot, which was not asked for.
