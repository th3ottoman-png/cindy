# 13.2a — Storage housekeeping probe (evidence)

- **Date:** 2026-11-14
- **Row:** ROADMAP 13.2a (probe, **no feature code**). Feeds ADR `0014-storage-housekeeping.md` and 13.2b.
- **Environment:** Node v22.23.4, Hermes installed **0.23.0** (pin 0.22.7, mismatch warning observed),
  dev app `CindyGlobal-dev2-dev` started from the canonical wrapper
  (`DESKTOP_DEV_VERDICT=ready`, pid 2713, CDP 9222, Vite 5174), commit `747ad72ded`.
- **Models used:** local only — `google/gemma-4-26b-a4b-qat` and `qwen3-8b` via LM Studio
  `http://127.0.0.1:1234/v1`. **Zero API turns, zero spend.**
- **Method:** read-only inventory; then a copy/delete/reopen/restore experiment on one old session,
  plus two control turns. UI driven through CDP (real composer + real Send button), transcript read
  from the rendered DOM and from SQLite.

All paths below are under `~/.hermes-cindy` (the Cindy home) or the dev profile's Application
Support directory. The daily Hermes home was never read, written or listed by this probe.

## 2. Experiment A — delete an old home, reopen, compare, restore

**Subject:** Cindy session `5be0ad2a-61d4-41af-9576-941039e6d1f9` ("11.7 Plan First live proof",
`active`, not pinned, no Orca role, last turn 2026-11-12), daemon session
`6a668e8f-ac0c-4cd4-ab0c-70c15eb341c9`, home `6a668e8f-…-78ec4534a3` (7.0 MB),
Hermes id `local-e674a60b…`, model `google/gemma-4-26b-a4b-qat` (local).
Baseline: **9 Cindy messages**, **4 Hermes messages** in the home's `state.db`.

**Backups before any write** (AGENTS.md §4):

- `cindy-local-v1.db.bak-20261114-13.2a` (6,488,064 bytes)
- `hermes-mgr/sessions.json.bak-20261114-13.2a` (101,060 bytes)
- full home copy `cp -a` → `/tmp/proofs/13.2a/home-original`: **98 entries / 7 symlinks / 7.0 MB**,
  copy's `state.db` verified to hold 4 messages and the original session id before deleting.
- No gateway owned the home (`gateway.pid` absent, no matching process).

**Steps and observations:**

1. `fs.rm(home, {recursive:true})` → home absent.
2. Reopened the session in the dev app (`location.reload()` then `#/cc-agent/5be0ad2a…`).
   **Full history still rendered.** DOM text 5860 chars vs 5830 baseline (delta = relative-time
   strings). All five history markers present, including
   `Session-based (Stateful)`, the `AUTH_NOTES.md` instruction and
   `I've written the line to AUTH_NOTES.md.`
   **The home was NOT rebuilt by reopening** — `homeExists=false` after the reopen.
3. Sent a recall question through the real composer and the real **Send message** button:
   *"Without using any tools: what exact line did you write into AUTH_NOTES.md earlier in this
   conversation? If you have no earlier conversation in your context, reply with exactly NO CONTEXT."*
4. Result in the transcript:

   ```
   Without using any tools: what exact line did you write into AUTH_NOTES.md …
   just now

   Hermes no longer has the previous session, so this message starts a new one.

   NO CONTEXT
   just now
   16.1k tokens
   ```

   The turn ran in a **new** daemon session `181fbeca-ef77-46f8-afe1-7e6f9f1688d6` → **new home**
   `181fbeca-…-73b7f5a6cf`, whose `state.db` contains exactly one session
   (`local-d831014d…`) and **2 messages**: the probe question and `NO CONTEXT`.
   The rebuilt home has 51 entries and the same 7 symlinks
   (`installs plugins .env auth.json SOUL.md skills memories`), a freshly generated `config.yaml`,
   `skills-manifest.md`, `auto-review.json` and an empty transcript.
   The old registry record `6a668e8f` was untouched (`lastSeq` 20, same Hermes id).
5. **Restored** the home from the copy: 98 entries / 7 symlinks, `state.db` 4 messages, original
   session id, and `diff -r --no-dereference /tmp/proofs/13.2a/home-original <home>` → **empty output**
   (byte-identical, symlinks compared as links).

**Answer to "does a deleted home rebuild with full history?"** — The home rebuilds **at the next
send**, not at reopen. The **visible** history is fully kept (it is Cindy's DB, not the home). The
**agent's own context is not**: the resume fails and the daemon starts a fresh Hermes session.
Experiment B shows this is not caused by the deletion.

## 3. Experiment B — control: an INTACT home behaves identically

**Subject:** Cindy session `ef62593b-1c5f-49f1-ae32-dd25180d3b58` ("Hi", `active`, not pinned),
daemon `4fddd2a8-9fbe-4e4a-b15e-28f6b12b8a36`, home `4fddd2a8-…-78e7e6dfe2` **left untouched**
(also copied aside to `/tmp/proofs/13.2a/control-home-original`, 4 messages). Its `state.db` contains
the marker `PONG_24B_CONFIRMED` twice. Model `qwen3-8b` (local). Backups:
`cindy-local-v1.db.bak-20261114-13.2a-control`, `sessions.json.bak-20261114-13.2a-control`.

Same question shape: *"What exact token did you reply with earlier in this conversation? If you have
no earlier conversation in your context, reply with exactly NO CONTEXT."*

```
[control] before: daemon=4fddd2a8-… hermesId=local-5910fc21… seq=24
[control] t+5s  daemon=7d61edff running=true  seq=2 hermesId=undefined
[control] t+25s daemon=7d61edff running=false seq=7 hermesId=local-4b0e9fad908f
[control] daemonSessionChanged=true hermesIdChanged=true
[control] home=…/7d61edff-1b90-44fd-930a-1eaeddf1506e-cfaed585b2 exists=true
[control] state.db sessions: [{"id":"local-4b0e9fad908f…"}]
[control] state.db messages: [user <available_skills>…, assistant "NO CONTEXT"]
```

Transcript: `Hermes no longer has the previous session, so this message starts a new one.` → **NO CONTEXT**.

**So the intact home lost its context too.** Root cause is in the code, not in housekeeping:
`packages/maker-core/src/agents/hermes/agent.ts` `startSession` does `const sessionId = randomUUID();`
and passes `resumeHermesSessionId` from the persisted `sdk_session_id`. A new daemon UUID means a new
`session-homes/<uuid>-<hash>` with an **empty** `state.db`, so `hermes chat --resume <old id>` cannot
resolve it; `isInvalidResumeFailure` (`hermes-run.ts`, pattern
`/no session found matching|session not found/i`) fires, the daemon emits `resume-reset` and replays
the input against a fresh session. There is **no state migration** between homes (no `state.db`
copy/adopt anywhere in `maker-hermes-manager` or the desktop host).

This matches the existing Debt row "Orphan Hermes session homes accumulate" (2026-10-29: "a resumed
session got a new `session-homes/…` after an app restart; the old home stayed"). What is new here is
the **proved consequence**: cross-restart continuation loses the agent's context every time.

## 4. Experiment C — within one app run the home IS required

Same session `ef62593b`, second send without restarting anything:
*"What was the exact text of your immediately preceding answer in this conversation? If you cannot
see any earlier answer, reply BLIND."*

```
[withinsession] before: daemon=7d61edff-… hermesId=local-4b0e9fad908f… seq=7
[withinsession] after:  daemon=7d61edff-… hermesId=local-4b0e9fad908f… seq=12
[withinsession] daemonSessionChanged=false hermesIdChanged=false
[withinsession] state.db messages: [user …, assistant "NO CONTEXT", user …, assistant "NO CONTEXT"]
```

Answer: **NO CONTEXT** (correct recall of its own previous answer), not `BLIND`. Same daemon session,
same home, transcript growing in that home's `state.db`. **Continuation within a run depends on the
home's `state.db`.**

|---|---|---|---|

An already-built venv does not read it. Sample archive file has `links=1` (not a hardlink into the venv) |

| `mcp_schema_cache.json`, `tool_discovery_cache.json`, `schema_columns.json`, `plugin_toolset_keys.json` | 3–32 KB | locally computed caches (`tool_discovery_cache` is keyed by absolute tool paths and is stale for a session home) | **Yes** — recomputed |
| `audio/ images/ screenshots/ videos/ documents/ browser-use/ scratch/` | **0 B** | tool working dirs. Scanned **every** home for `image_cache`, `audio_cache`, `cache/images`, `cache/screenshots`, `cache/videos`, `cache/documents`: **zero files anywhere** | **No** — generated artifacts. Empty today, so the rule must be conditional, not blanket |

`models_dev_cache.json` sits at the **top level** of each home (not in `cache/`), 5.7–5.8 MB, with a
`models_dev_cache.etag` companion (`W/"39fcecfbcb2d708ed0b519682b7a3c6f"`) — an HTTP-cached remote
model catalog. **143 copies = 836 MB.** Re-downloadable.

**Caveat for "bytes freed":** uv on APFS may clone files rather than copy them, so `du` can overstate
what a deletion actually returns to the volume. 13.2b must report freed bytes honestly (measure, or
label the number a `du` estimate).
