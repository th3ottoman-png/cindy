## 8. Bugs found and fixed during the proof (same commit)

1. **First-join dispatch lost to an acceptance race.** A queued teammate dispatch is accepted
   asynchronously; when acceptance landed after the send wrapper returned, the lead's own send had
   begun recycling the lead runtime and the Orca delivery guard cancelled the join prompt
   ("Task permissions are changing"), silently losing the teammate's first task (the lead then
   improvised via `delegate_task`). The teammate dispatch now waits for the worker to actually accept
   before returning, with a bounded retry. Re-proven: first join now dispatches, the worker answers,
   and the lead waits for the report.
2. **`expert:<slug>` binding refused.** `bindSession` keeps bare expert slugs (or full imported ids);
   the roster `expert:` prefix was passed un-normalized → `invalid expert "expert:geographer"`.
   12.3a only exercised imported ids, so this was latent. `teammateBindingId` normalizes the roster id
   before binding. Re-proven: the Geographer binds (`slug:"geographer"`) and runs in role.
3. **Picker cold-start subscription.** A cold-start mount can subscribe before the owner-namespaced
   draft key settles, so the trigger was missed on the first navigation. The slot is keyed by data
   owner and carries a light 250 ms poll as a safety net. Re-proven: the picker opens on a clean mount.

## 9. Negative case

`propose_teammate` refuses when the caller is not an opted-in teammate (`canPropose` false →
`TEAMMATE_PROPOSE_NOT_ENABLED`), when the roster id is malformed, when the target is already joined,
and when the entry cannot run on Hermes — all pinned by unit tests
(`teammateProposalService.test.ts`, `orca-bridge-mcp.test.ts`). The live negative attempt was slowed
by the local model's turn contention; the refusal path is covered by the unit suite.
