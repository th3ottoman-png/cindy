## What was built

- NEW `packages/maker-hermes-manager/src/web-budget.ts`: narrow reader for `web-budget.yaml`
  (`max_searches_per_session` default 50, 0 = unlimited, upper bound 10 000; `tool_names` default
  `[web_search, web_extract]`; unknown keys and bad values are listed and fall back to their default;
  a missing file gives the defaults), a 2 s cached loader, `webCallsIn` (direct web tools **and** web
  calls inside Hermes's `tool_call` batch wrapper), and `WebBudget`: per-session count that **reserves**
  before the rest of the review and **releases** when the call ends up blocked, so parallel calls cannot
  both take the last slot; a wrapper's inner calls are remembered for 120 s so a hook that also fires
  for each inner call does not count them twice. Block reason:
  `web-search budget reached (N/N) — this call did not run. Answer with what you already found; the
  owner can raise the cap in ~/.cindy-harness/web-budget.yaml or start a new session.`
- `hermes-manager.ts`: the `AutoReviewGate` handler is `webBudget.review(…, () => reviewOrGuard(…))`,
  so the budget answers first; `homeForSession` installs the hook when `autoReview || guardArmed ||
  budgetArmed`; with the guard off, a budget-only hook allows a counted call instead of the "no longer in
  Auto-review" block; the count resets on a new daemon record (new conversation, or after `/clear`,
  which closes the record) and on `query/close`. New RPC `session/webBudget` → `{used, max, toolNames,
  errors, file, enforced}`; `enforced` is false where Hermes never runs the hook (Default / safe mode,
  chat-only, no per-session homes, no hook command, cap 0). Bundle 0.3.0 → **0.3.1**.
- Desktop: IPC `maker:web-budget:get` (`main/maker-ipc/webBudget.ts`, maps the Cindy id to the 1.14
  daemon id; any failure reads as unavailable), preload + `vite-env.d.ts`, and `WebBudgetChip` in the 8.2
  session manifest strip (`web N/M`, re-read every 4 s while visible; `web –/M` when not enforced,
  `web no cap` at 0; tooltip names the tools, the file and any file problems).
- `@cindy/maker-core/hermes-daemon-session-id` subpath export (the existing 1.14 helper, unchanged).

## Findings

1. **Blocked calls are not in Cindy's transcript.** Cindy's DB holds only the two `tool_use` rows that
   ran; the two hook-blocked calls are visible only in Hermes's log, the chip and the model's reply.
   Pre-existing behaviour of the hook path (a guard block is not shown either), not changed here.
2. **Default mode is not covered.** Default sessions run `--safe-mode`, which ignores config and
   hooks, so the cap cannot apply there (30 of 181 registered sessions are Default). The chip says so
   (`web –/M`, tooltip names Full access and Auto-review). Documented, not worked around.
3. **No new hook cost today.** The guard is armed (`security.json` `policy: hold`), so every Full
   access and Auto session already carries the hook; a non-zero cap adds nothing. With the guard off,
   the default cap of 50 now installs it — the trade-off the blueprint accepts.
