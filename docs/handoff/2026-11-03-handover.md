### What 1.11 taught us (do not re-discover)

- Hermes 0.22.5 compresses on its own and only logs it, to `<session home>/logs/agent.log`:
  `context compression started: session=… tokens=~N` and `context compression done: … rough_tokens=~M`.
  The daemon follows that file during a turn (`createCompressionWatcher` in
  `packages/maker-hermes-manager/src/hermes-context.ts`) and emits `hermes-mgr/compression`. The Hermes
  agent (`packages/maker-core/src/agents/hermes/agent.ts`) shows "Compacting context…" and stores the line
  "Context compressed automatically: A → B tokens." as a chat message.
- There are three trigger paths and all log the same lines: in the tool loop (mid-turn), turn-start
  preflight (once the last real count plus the new message pass the limit), and gateway "Session
  hygiene" at the next turn start. ADR 0010 originally said plain turns never compress; that was wrong
  (Addendum).
- The limit is 85% of the compressor window. Today that window is 65,536 for every model, so the limit
  is 55,705. That 65,536 is exactly the 1.12 bug.
- **Failure mode:** a chat of a few huge messages has nothing compressible ("Compression made no
  progress"). If such a turn is over 65,536, Hermes refuses it ("could not bring this session under the
  model's context window … Start a new session with /new") and resets its own session. Hermes then loses
  the history; Cindy keeps its rows.
- After the Hermes gateway restarts (600 s idle, `gateway.unmanaged_idle_exit_seconds`), one turn may go
  out uncompressed before the count is known again. Not fixed; it would need a gateway that never idles.

## 4. Next task: 1.12b (needs one owner decision)

**Cause** (STATUS 1.12a): `model.ollama_num_ctx: 65536` in `~/.hermes-cindy/config.yaml`, added
2026-11-01 for 2.2b-2 so small local models pass Hermes's 64k floor. Hermes 0.22.5
`agent/agent_init_ollama.py` `_clamp_compressor_to_ollama_num_ctx` lowers the compressor window to that
value on **any** endpoint. So deepseek-flash (about 1M tokens) and Gemma on LM Studio (262k) both run at
65,536.

**Options the linked session recommended (the owner picks):**

1. A new daemon config RPC that removes the global key and writes a `custom_providers` entry with
   `base_url` + `context_length` per local endpoint (LM Studio `127.0.0.1:1234`, Ollama
   `127.0.0.1:11434`). Probe E proved this works. Caveat: that window counts as the model's real window,
   so it must not exceed what the local server has loaded.
2. The daemon writes `ollama_num_ctx` only into the session homes of local routes.

## 6. Working rules and gotchas learned this session

- **Node 22 first:** `export PATH="/opt/homebrew/opt/node@22/bin:$PATH"`; `node -v` must say v22.
- **Gates before every commit:** `pnpm typecheck`, `pnpm test:runner`, `pnpm check:test-hygiene`,
  `pnpm test:unit:related`. The desktop tier often dies with the known threads **SIGSEGV** (the runner
  then reports `TEST_ASSERTION_FAILED`; check that the only failure line is the SIGSEGV). Then run the
  desktop tier as 8 shards and rerun only a crashed shard:
  `XDT_UNIT_TEST_SHARD=i/8 node scripts/test-workspaces.mjs --tier unit --workspace apps/desktop`.
  All 8 green counts as the gate.
- **Commits:** `git commit -s`, imperative subject under 72 chars, push to `origin main`, never force.
  Every session ends with ROADMAP + STATUS edits (HANDOVER.md only for stable changes).
- **Hermes source:** the installed code sits inside the owner's daily Hermes home (off limits). Read the
  public tag instead: `https://codeload.github.com/NousResearch/hermes-agent/tar.gz/refs/tags/v0.22.5`,
  unpacked in your scratchpad.
- **Probes:** use a throwaway `HERMES_HOME` in your scratchpad with a small Node stub model on
  `127.0.0.1` (OpenAI-compatible, `usage.prompt_tokens` = request chars / 4). Run the real
  `hermes chat --format stream-json --query-file - --in <dir> --yolo [--resume <id>]`. Afterwards kill
  only the probe's gateway: check its `HERMES_HOME` with `ps eww -p <pid>`. The owner's Cindy gateway
  is also running.
- **zsh gotcha:** an unquoted `$R` holding `--resume <id>` stays one argument. Use bash for such loops.
- **Compression tests need a realistic chat:** many medium messages (about 4–5k tokens each), not a few
  huge ones (§2).
- **Cindy DB (read only):** `~/Library/Application Support/CindyGlobal-dev2-dev/cindy-local-v1.db`,
  table `messages` (`session_id`, `role`, `content`, `created_at` ms); `sessions.context_tokens`.
  Open with `sqlite3 -readonly`.
- **Hermes per-session logs:** `~/.hermes-cindy/session-homes/<id>/logs/agent.log`.
- **Driving Cindy yourself:** the dev app's bundle id is `com.github.Electron`. An invisible
  QuakeNotch window blocks full-screen clicks; use the background `app_*` tools. Full-screen control is
  needed only for Cmd+V (clipboard paste); copy with `pbcopy` from Bash first.
- **New main-process code needs a full app restart** (quit the app, stop `pnpm dev`, start again).
- **Untracked, deliberately not committed:** `.kimi-code/`, `.serena/`, `.specify/`, `.workbuddy-ai/`
  (other tools' local config) and `apps/desktop/src/renderer/__tests__/tmp-probe/` (a leftover probe
  test from 1.11a). Leave them alone unless the owner says otherwise.
