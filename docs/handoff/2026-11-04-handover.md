## 1. What this project is (one paragraph)

Cindy is the owner's private, single-user fork of an Electron desktop agent app. The owner uses it
as a daily driver with **Hermes** (Nous Research's agent CLI, pinned to 0.22.5) as the main agent.
Hermes runs as one `hermes chat --format stream-json` child per turn, managed by the `hermes-mgr`
daemon (`packages/maker-hermes-manager`). The Hermes adapter lives in
`packages/maker-core/src/agents/hermes/`. The Hermes home is `~/.hermes-cindy`. **Never read,
write or name the owner's daily Hermes home** (AGENTS.md §1). `HANDOVER.md` has the architecture,
commands and versions.

## 5. Working rules and gotchas (accumulated; do not re-discover)

- **Node 22 first:** `export PATH="/opt/homebrew/opt/node@22/bin:$PATH"`; `node -v` must say v22
  (v22.23.4 at handover). Node 26 on PATH breaks `better-sqlite3` (`NODE_MODULE_VERSION`).
- **Gates before every commit:** `pnpm typecheck`, `pnpm test:runner`, `pnpm check:test-hygiene`,
  `pnpm test:unit:related`. The desktop tier intermittently dies with the known threads-pool
  **SIGSEGV** (never count a crashed run as green). Working form:
  `XDT_UNIT_TEST_SHARD=i/8 node scripts/test-workspaces.mjs --tier unit --related --workspace apps/desktop`
  for i=1..8, rerunning only crashed shards; 8/8 green counts as the gate. `pnpm test:unit:related`
  itself can fail to resolve its git base and exceeds a 300 s tool cap; the sanctioned equivalent
  is the explicit split: `node scripts/test-workspaces.mjs --tier unit --related --exclude-workspace apps/desktop`
  plus the 8 desktop shards. Docs-only commits: typecheck + runner + hygiene suffice (house pattern).
- **Commits:** `git commit -s`, imperative subject < 72 chars, push to `origin main`, never force.
  Every session ends with ROADMAP + STATUS edits (HANDOVER.md only for stable changes) and a dated
  vault line. Stage only your task files; never stage the untracked junk in §6.
- **Hermes source:** the installed code sits inside the owner's daily Hermes home (off limits).
  Read the public tag instead:
  `https://codeload.github.com/NousResearch/hermes-agent/tar.gz/refs/tags/v0.22.5`, unpacked in
  your scratchpad.
- **Probes:** throwaway `HERMES_HOME` in your scratchpad, small Node stub model on `127.0.0.1`
  (OpenAI-compatible), real `hermes chat --format stream-json`. Kill only your probe's gateway
  (check its `HERMES_HOME` with `ps eww -p <pid>`); the owner's Cindy gateway is also running.
- **zsh gotcha:** an unquoted `$R` holding `--resume <id>` stays one argument. Use bash for loops.
- **Cindy DB (read only):** `~/Library/Application Support/CindyGlobal-dev2-dev/cindy-local-v1.db`
  (`sqlite3 -readonly`), tables `messages` and `sessions`.
- **Hermes per-session logs:** `~/.hermes-cindy/session-homes/<id>/logs/agent.log`.
- **Driving the dev app's UI:** with the display unlocked, kimi-cu background `app_*` tools work
  (an invisible QuakeNotch window blocks full-screen clicks; Cmd+V needs full-screen). With the
  display **locked**, kimi-cu cannot help — drive the renderer over the app's CDP port instead:
  the dev build binds `127.0.0.1:9222` (see `docs/dev-rules/desktop-development.md`; note
  HANDOVER.md §2 mentions 9333/`XDT_CDP_PORT` — 9222 is what dev actually bound). A tiny Node-22
  script with the built-in WebSocket client doing `Runtime.evaluate` is enough for navigation,
  clicks, form fills and assertions.
- **New main-process code needs a full app restart** (quit the app, stop `pnpm dev`, start again).
  Renderer-only changes hot-reload; if the UI hits "No handler registered", main is stale.
- **New renderer surfaces:** run `node scripts/design-inventory.mjs` or `pnpm test:runner` fails.
  Typography: placeholders use `--text-placeholder`, not `--text-tertiary` (the ink-ladder test
  in shard 8 catches it).
- **Hermes facts proven along the way:** no skill disable mechanism (4.4b moves folders to
  `skills-disabled/`); `requires_toolsets` in a SKILL.md makes `hermes skills list` silently omit
  the skill (`devops/sdlc-review` needs `kanban`) while the file and bundled manifest still list
  it; `disabled: true` on `mcp_servers` is ignored at startup; `-t/--toolsets` is fixed at session
  creation and a resume must repeat it exactly or omit it.
- **Owner's vault:** `/Users/turko/Bishi-memory/memory/Project — Cindy.md` — append a dated line
  at the END (chronological), matching the existing format.
- **One question rule:** ask the owner only when a real product decision is needed (e.g. the 3.2b
  `tools.yaml` schema), and ask one question. Everything else, answer by reading the repo.
