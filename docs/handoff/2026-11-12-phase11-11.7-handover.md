## 2. Two known bugs in the renderer drafts (fix first — both verified, not guesses)

1. **Wrong send params.** `DecisionCards.tsx` reads `snap.model`, `snap.permissionMode`,
   `snap.workingDir`, `(snap as any).effort` off `makerChatStore.getSnapshot(sessionId)`.
   `SessionChatState` (makerChatStore.ts lines 2552–2954) **declares none of those fields**
   (only comment mentions) — this will fail typecheck. The view's own send call
   (`CCAgentSessionView.tsx` ~4296) passes `model, effort, permissionMode` from its scope
   and `session.workingDir` from the session row. Fix: pass the four send params as props
   into `DecisionCards` from the mount site (which has session context), or lift
   decide+send into a parent callback prop. Do not keep the `as any` cast.
2. **Wrong i18n namespace.** Both components use `t('ccAgent.planFirst.*')`, which does not
   exist. `t()` returns the key string on miss, so the `?? 'literal'` fallbacks **never
   fire** — the chip would render raw key text. Precedent `ChatOnlyToggle.tsx` uses
   `t('chat.chatOnly.*')` with real keys at `chat.chatOnly` in
   `apps/desktop/src/renderer/i18n/locales/en/common.json` (line ~12793). Fix: add a
   `chat.planFirst` block (label, hint, locked, lockedHint, decided, sending, proceed,
   failed) to **en only** (UI is English-only by decision; no translations for new
   strings), and switch both components to `t('chat.planFirst.*')` without `??`.
