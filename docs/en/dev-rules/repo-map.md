# Repository Map (Repo Map)

> **When to read**: on first contact with this repo, when locating the code of some feature, or before adding code/dependencies, to judge
> which module it belongs in

This document only does **location/navigation**: first find production entry points, shared criteria, and tests by user behavior, then judge code ownership by directory.
The sources of truth are each directory's source code, `package.json`, and READMEs; when this document is found inconsistent with the code, the code wins and this document should be fixed along the way.
For dependency direction and decoupling constraints see [`architecture-invariants.md`](../../dev-rules/architecture-invariants.md).

## Top-level structure

| Path        | Description                                                                                                                           |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `apps/`     | End-user products (desktop, mobile) and binary assets distributed with the package                                                              |
| `packages/` | Client shared capability packages (decoupled from render/main; see table below)                                                                             |
| `config/`   | Regional endpoint manifests (CN / Global public configuration and local dev templates); for local configuration preparation of new worktrees see [environment setup](../../dev-rules/environment-setup.md) |
| `scripts/`  | Repo-level engineering scripts: dev launch wrapper, agent binary fetching (`ensure-agent-binaries.mjs`), i18n/endpoint/docs validation guards, worktree management |
| `tools/`    | Version pins (`latest.json`) and updaters (`update.mjs`) for the four Desktop runtimes: claude/codex/ripgrep/pi                            |
| `docs/`     | Rule documents: `dev-rules/` (engineering), `product-rules/` (product), `design-rules/` (design entry), `legal/`, etc.                             |

## apps/

| Path                                                         | Description                                                                                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/desktop`                                               | Cindy desktop client (Electron + Vite); source split into `main/` (main process: business logic, maker-host/maker-ipc, localDb, device-link, mcp-integrations, cindy-brain, etc.), `renderer/` (pure rendering UI: features, panels, themes, i18n, etc.), `preload/` (minimal bridge layer), `shared/` (types and constants shared between main/renderer); SQLite migrations in `apps/desktop/drizzle/` |
| `apps/mobile`                                                | Cindy mobile client (Expo / React Native): same-account login, discovering and remotely controlling desktop devices, mirroring sessions                                                                                                                                                                           |
| `apps/claude-code-bin`, `apps/codex-bin`, `apps/ripgrep-bin`, `apps/pi-bin` | Precompiled CLI binaries distributed with the desktop client (in per-platform directories). Not build packages, not in git history; versions pinned by `tools/<kind>/latest.json`, downloaded on demand by `pnpm install` postinstall |
| `apps/android-platform-tools-bin`                            | Android platform-tools (adb, etc.) binaries, currently win32-x64 only, used for connecting Android devices                                                                                                                                                                                      |

## Local-app Agent access

Desktop's `main/local-agent/` provides a general local-machine Agent API authorized through Cindy-themed confirmation, reusing maker-core's engines and in-memory Sessions; the app's own UI, records, context, and business tools stay with the caller. Protocol, storage, and compatibility boundaries: [local-app access](../../local-agent-api.md); standalone client examples in `scripts/examples/`.

## Verified downloads and tool installation

Desktop release assets uniformly go through `main/downloader/index.ts`; general tool installation lives in
`main/managed-tools/`. For integration methods and boundaries reserved for each business see
[verified downloads and managed tool installation](../../dev-rules/verified-downloads.md).
